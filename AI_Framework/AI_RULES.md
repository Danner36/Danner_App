# AI Rules

Read this file before any other work in this repository. Then read [AI_ONBOARDING.md](AI_ONBOARDING.md).

## Context files

- At task start, read every tier `README.md` from the repository root down to the working directory before exploring code or editing files.
- For cross-cutting tasks, read the context chain for every edited directory tree.
- At task end, update a tier README only when its directory boundary, responsibility, or non-obvious invariant changed.

## Environment

- Development target is Windows.
- Prefer PowerShell for shell commands.
- If a local preview server is added, prefer port 8108, then scan 8108 through 8127. The test harness uses 8108 (fixture server), 8109 (Cast web), and 8111 (Get video mock).
- Physical iPhone install, SideStore, IPA sideload, and signing refresh follow [IPHONE_INSTALL.md](IPHONE_INSTALL.md). Windows has no iOS ADB and no Xcode.
- Do not print Apple Account emails, passwords, 2FA codes, pairing files, device UDIDs, Google or YouTube TV account data, any listing-site URL including backup sources, the family PIN, or the app key.
- `main` has no required status checks or required pull requests, because the stream pipeline bots commit to it directly. Do not force-push or delete `main`; the `Protect main` ruleset blocks both (`Docs/Production/ModularTeams.md`, Decided 19).

## Generated material

- No troubleshooting or best-practice asides in generated material.
- Avoid stock filler, hype language, and slanted text.
- Drop abandoned work silently.

## Comments and documentation

- Comments are not conversational and do not use `we` or `user`.
- Comments and docs describe current behavior only. `Docs/Production/` briefs with a `Status:` header may describe planned work.
- Keep validation results synchronized with [../Docs/Production/Validation.md](../Docs/Production/Validation.md).

## Edits and communication

- Summarize the implementation scope before editing.
- Documentation writes require owner approval.
- Keep changes surgical when a local edit is sufficient.
- Report what was attempted and request device verification for behavior that cannot be proven locally.
- Provide a sorted, repository-relative list of touched paths at handoff.
- Default to concise, high-level replies.

## Product constraints

- `Docs/Production/ModularTeams.md` is the approved delivery plan. Work inside a plan phase follows the plan where it differs from a constraint below; each phase rewrites the constraints it changes. `Docs/Archive/FixedTeams/` and tag `fixed-teams-final` are history, not constraints.
- Preserve the Danner family app hub, the selected teams' screens, the fixed TV Location tile, the YouTube TV playback-area purpose, and parent-friendly interfaces on Android and iPhone.
- Allowed verification URL: `https://tv.youtube.com/verify` and redirects initiated by that page. `Sign in` and `Switch account` open that page or Google's account chooser with a `tv.youtube.com` continue target, inside the same top-level `youtube.com` and `google.com` gate and with no injection.
- TV Location has no compiled location. First use requires a choice on the map before steps 2-4 open. The default (`danner.tv.default.v1`) and the current point (`danner.destination.v1`) are stored only on the phone.
- Let the destination be chosen from the bundled U.S. map or offline city search, display the nearest town or city rather than coordinates, and save the point locally for later launches. A phone holding only a current point keeps it and that point becomes its default. `Forget location` removes both keys after a confirmation; no other code clears or renames them.
- Inject the selected coordinates into the verification WebView's browser Geolocation API. Do not modify device GPS, request device location, launch a separate mock-location app, or claim that phone location changed. TV Location does not read GPS. Android Cast uses Nearby Wi-Fi with `neverForLocation` and does not declare or request fine location.
- Keep the main hub logo-only, with no menu headings, prompts, or tile descriptions. Tiles are the selected teams in stored order, then TV Location (fixed, cannot be removed), then `+`. A first install shows TV Location and `+`. The grid grows and the tiles scale from 101.2dp, the grid scrolls below 64dp, and a hub holds at most 30 team tiles; at the cap `+` stays and the picker shows `Hub is full (30 teams)` with adding disabled. Layout values live in `app/hub/hubGrid.ts` and `Docs/Art/README.md`. A long press opens `Move to front`, `Move earlier`, `Move later`, `Change sports` (schools only), `Remove from hub` with a confirmation, and `Cancel`, and the same actions are accessibility actions. There is no drag reorder.
- `+` opens the picker: league or college sport, then team or school, then sports for a school. A league or sport appears only when the build has its adapter and the catalog marks it `pickable`; `retired` and `hidden` entries and `retiredSports` are not offered. A pro team has its own tile. Sports from one school share one tile: adding a sport merges into it, and the tile goes away only when its last sport is removed. Removing a tile deletes its sources cache and logo file. `app/picker/catalogSnapshot.json` is the catalog bundled for offline use, written only by `npm run build:catalog-snapshot`, and each file is replaced by its `danner.catalog.v1` copy when that copy is newer. A 24-hour cache refresh updates stored tiles' display data by key and never their order or sports.
- Preset seeding runs only when `danner.selection.v1` and `danner.seed.v1` are both absent. Any of `danner.install.v1`, `danner.guardians.sources.v2`, `danner.patriots.sources.v1`, `danner.cyclones.sources.v1`, or `danner.destination.v1` (layer 1), else an Android `lastUpdateTime` minus `firstInstallTime` over 60 seconds (layer 2), seeds Guardians, Patriots, and Cyclones; anything else is a first install. The selection is written before `danner.seed.v1`, and the three v1 sources keys are removed only after both writes succeed. Seeding never writes a TV key, and this app never writes `danner.install.v1`. `tiles: []` means every tile was removed; the key is never deleted. A storage call that throws or takes longer than 3 seconds, an unreadable selection, or a newer schema makes the session read-only: no seeding, no writes, and the stored key is never overwritten or deleted. The splash screen holds until the selection has loaded.
- Team logos come only from `https://a.espncdn.com/` and are stored as `logos/<TeamKey>.png` under the document directory, indexed by that relative name in `danner.logos.v1`, and resolved against the current directory at runtime. The cached file wins, then the abbreviation on the accent color.
- On iPhone only, allow the signing-health exception above the Danner logo during the final 48 hours of the embedded provisioning profile. Keep it to the expiration text plus `Connect to Wi-Fi and charge phone to fix`. Do not show it when more than 48 hours remain, when no embedded profile exists, or on Android.
- When a published GitHub release is newer than the embedded build version, the hub may show a yes/no update prompt on launch and when returning to the hub. Do not show it while the iPhone signing-health warning is visible, while a team screen, the picker, TV Location, the tile actions, or a confirmation is open, or when the baked release version is absent. No dismisses the prompt until the app process exits. Android Yes downloads the release APK, verifies SHA-256, and opens the system installer; while it downloads, the hub shows only a small spinner, and once the installer opens or is cancelled the prompt stays dismissed until the app process exits. iPhone Yes opens SideStore with `sidestore://install?url=` for the release IPA. LocalDevVPN on Wi-Fi is still required for that SideStore install.
- Every team screen (`app/team/TeamScreen.tsx`) fetches its record, games, and remaining schedule when opened, on pull-to-refresh, and every ten minutes. A live featured game also refreshes its board every five seconds while the screen is open. A pro tile promotes an in-progress game, today's next game, or today's completed-game recap above the schedule. A school tile gives each game today its own featured card that names the sport: Live games first, then today's games that have not finished, then today's finals, each group in start order, so overlapping or same-day games each show their own score, board, Play, Listen and Get video. Today's scheduled game shows a one-second countdown when a start time is published. A game with an unknown start time shows `Time TBA` and does not count down or open Play before it is live. Delayed, postponed, suspended, and canceled games state that condition directly. After Final, the featured card shows `WIN`, `LOSS`, or `TIE` and the score through local midnight of the recap day, without the live board, Play, Listen, or Get video. Never show completed games in the schedule; every date and time on screen is in the phone's time zone, and the official date is a hidden matching key. Sport labels appear only on a tile with more than one sport. A failed season-type list carries that adapter's previous games, record, and postseason status forward; a record is never computed from part of a schedule.
- MLB adapter: statsapi with the team id and league id from `TeamRef.statsapi`. Official date is the statsapi official date. `startTimeTBD` is the unknown start time. Warmup is pre-game. ESPN serves MLB only for win chance and logos.
- Each team's playback list is `streams/<league>/<espnId>.json`, through Worker v2 (`GET /streams?team=<key>`) when `EXPO_PUBLIC_DANNER_WORKER_URL` is set, then raw GitHub `main`, then the last valid copy in `danner.sources.<TeamKey>.v1`. A Get video session also tries raw GitHub by the file's latest commit SHA after the Worker fails. Streams are read on open, pull-to-refresh and foreground, and every minute only while a game is Live or from 45 minutes before its start to the end of its grace period. A later fetch that has no featured-game match does not wipe a URL the phone already has. An entry with `eventId` matches that id on its current official date; an entry without one matches official date and game number; school files also match `sport`. The parser ignores unknown keys. Show icon-only Play actions starting 15 minutes before game time, and for any Live game; if no matching URL is ready, say so and keep checking automatically. When `EXPO_PUBLIC_DANNER_WORKER_URL` and `EXPO_PUBLIC_DANNER_APP_KEY` are set, show **Get video** in that same window. Get video POSTs `{ appKey, team, sport?, eventId }` and polls `GET /streams?team=<key>&event=<id>` for up to 900 seconds, showing plain progress text and never a site name or host. A matching `direct` source also shows Listen. Direct sources expose a header Cast control; `web` sources expose a header TV control that relays a page-reported HLS, DASH, or MP4 URL from a phone origin when the injection names a matching content type; YouTube stays phone-only. The relay exists because the provider answers its playlists only for its own page and its segments carry no CORS header. That relay is loaded as a live stream when the source is live, forwards the highest video variant at or under 3.5 Mbps when one exists (otherwise the lowest video variant), and prefetches the live-edge segments. The screen-capture converter is archived under `reference/screen-capture-hls/` and is not built. Isolated `web` pages on iPhone report an Android Chrome user agent so the page serves the same player build as Android. HTTPS is the default; cleartext HTTP is accepted only when that entry sets `allowInsecureHttp: true`. Prefer direct media in the native player; isolate YouTube and other approved player pages in restricted WebViews. Intercept new-window requests, promote only targets on the source's exact trusted hosts into the isolated player, and discard all other popup targets without loading them.
- Fixtures stay under `tests/leagues/` and `tests/team-harness/`, are served from port 8108 (Get video mock 8111), and can be read only by a development build with `EXPO_PUBLIC_TEAM_TEST_URL` and `EXPO_PUBLIC_TEAM_SOURCES_URL` set; `EXPO_PUBLIC_TEST_SELECTION` and `EXPO_PUBLIC_TEAM_CATALOG_URL` are development-only too. Never import test fixtures into the Expo asset graph or enable the harness in production. ESPN captures for board tests live under `tests/leagues/<adapter>/` and `tests/scoreboards/archived/`.
- NFL adapter: ESPN NFL site JSON for preseason, regular season, and playoffs. The hero record is regular-season W–L or W–L–T and stays `0–0` until a regular-season game is Final. A live game refreshes a football board (quarters, clock, down and distance, possession). Official dates are the America/New_York calendar date of kickoff.
- NCAA adapters: ESPN NCAA site JSON for football, men's basketball, and women's basketball, one record per sport, each staying `0–0` until that sport has a regular-season Final. Each Live card refreshes its own football board or basketball arena board every five seconds. Elimination is an explicit status on a knockout loss with no later game; only College Football Playoff games are knockout bowls. Selection Sunday, pairing, a basketball conference-tournament result, and a win with no next game posted show `Awaiting next` and are not eliminated. Official dates are the America/New_York calendar date of the start; a `Time TBA` game takes the same date of ESPN's placeholder time.
- The basketball arena board, for every basketball adapter, shows only values derived from the ESPN summary the live poll already fetches, plus the Core `…/competitions/{id}/situation` resource only when the timeouts sub-decision of `Docs/Production/ModularTeams.md` (O27) turns it on. A team's players are labelled as on the floor only when its substitution replay passes the consistency check, or, with the adapter's `activeLineup` flag on, the `active` check; otherwise that team's table shows top scorers under a `TOP SCORERS` caption. Timeouts left come only from an ESPN field that holds them, never from timeout plays and allotments. A cell whose capability flag is off is omitted. The board carries no logos or other branding, and team names are text.
- Pure modules (`app/team/engine/`, `app/leagues/`, `app/scoreboards/basketball/` except `BasketballArenaBoard.tsx`, `app/selection/` except `store.ts`, `app/hub/hubGrid.ts`, `app/picker/catalogModel.ts`, `app/logos/logoPlan.ts`, `app/streams/sources.ts`, `app/tvLocation/destination.ts`) have no runtime React Native import and import siblings with explicit `.ts` extensions, so they run under plain Node.
- Every featured card shows a `WIN CHANCE` bar under the matchup line with `Us` and `Them` percentages and no source name. It reads ESPN's pre-game prediction, then ESPN's newest live win probability, refreshed every ten minutes before the game and every 30 seconds while live. Hide it after Final, for postponed and canceled games, and whenever ESPN has no number; a failed request never blocks the countdown, Play, or Get video. When no game is featured, the first schedule row shows the same bar.
- Android WebViews never set `incognito`, because it clears every WebView cookie in the app and signs TV Location out of Google. Team player WebViews use `incognito={Platform.OS === 'ios'}`.
- On Android, TV Location writes the WebView cookie store to disk while a YouTube or Google page is open, when the app leaves the foreground, and when that page closes. `Sign out` on Android and iPhone clears the YouTube session after a confirmation and leaves the location and steps unchanged; on Android it clears every WebView cookie and all web storage in the app, because `CookieManager` has no per-domain delete.
- Inside `TV Location`, keep four explicit guided steps, large controls, large text, highlighted current work, automatic scrolling to the next action, and clear completion/retry states. Step 3 exposes only its update button, returns to step 4 after YouTube's `Next` control is activated and the page changes, and does not expose coordinate-bridge diagnostics. Step 4 identifies the `Welcome to...` message as appearing on the TV. The `On this phone` panel sits outside the cards, below step 4, with no step number. The app has no credential fields, stores no password or Google cookie value, never shows the account email, and passes only a signed-in state across the native bridge. The geolocation injection runs only on `youtube.com` and `*.youtube.com` hosts.
- Platforms: Android and iPhone from one Expo app.
- Distribution: direct device installation only. Produce an installable signed APK for Android and a SideStore-compatible IPA for iPhone. Each GitHub release carries both Danner artifacts, `release/IPHONE_SETUP.md`, `version-manifest.json`, and `sidestore-source.json`. That setup card links to the official LocalDevVPN App Store listing, SideStore instructions, current iLoader release, and Apple's 64-bit iTunes download; do not mirror third-party binaries. iLoader on Windows requires Apple website iTunes (not the Microsoft Store) so Apple Mobile Device Service can see the phone. A logged-in iLoader session may also `Import IPA` over USB. Use a free dedicated Apple Account and any working Wi-Fi for SideStore renewal; cellular data alone is not a supported refresh path. Do not require paid Apple Developer membership or add app-store submission work.
- Bake the GitHub release tag into `expo.version`, Android `versionCode`, and iOS `buildNumber` during the release build (`major * 10000 + minor * 100 + patch`). Release tags are `vMAJOR.MINOR.PATCH` with digits only and minor and patch from 0 to 99. Local and development builds without `RELEASE_TAG` keep version `1.0` and code 1. Keep minimum SDK 29 and the current target SDK required by the maintained toolchain. Do not rotate the Expo debug keystore used by family APKs. The Android package `com.example.location_helper`, the iOS bundle id `com.danner.locationhelper`, and the debug keystore never change, and versionCode strictly rises, so on-phone data survives updates. AsyncStorage keys carry a version suffix; a new version is written by migration, and the old key is removed only after the new write succeeds.
- Branding: Danner green and white script logo in `Docs/Art/media/ic_launcher_danner.jpg`.
