# Why the iPhone install dies after a week (investigation of 2026-10-09)

Phone: the household iPhone 14 Pro on iOS 26.6.2, SideStore 0.7.0 nightly (build 20260914.1447), LocalDevVPN 1.3.0, Danner Apps 1.4.11. Method: everything below was read from the phone over USB with [the harness](README.md); nothing was changed on the phone except two launch attempts. Times are UTC unless marked ET (New York, UTC-4).

## What the owner sees

Tapping Danner Apps or SideStore shows an iOS dialog, `"Danner Apps" Is No Longer Available` / `"SideStore" Is No Longer Available`, with one OK button. That is iOS refusing to launch an app whose free-developer provisioning profile has expired. It is not an iLoader message; iLoader has no "expired" message at all. Once SideStore itself is in this state the charger Shortcut can do nothing, because `Refresh All Apps` runs inside SideStore.

## Root cause

1. **SideStore's Apple session died and SideStore never signs in again by itself.** Its `AuthManager.getAuthenticatedSession()` rebuilds the session from the Xcode auth token stored at sign-in time plus fresh anisette data. When Apple rejects that token, every refresh fails until a person opens SideStore and signs in. The stored password is only used by the interactive sign-in flow (it also needs the 2FA prompt). This token lasted nine days here (09-14 to 09-23).
2. **The password itself appears to have changed or been invalidated around then.** iLoader's saved login for the same account was rejected by Apple on 2026-10-09 with `Auth error -22406: Enter the correct password for this Apple Account.` The owner has to sign in with the current password in both iLoader and SideStore; no tool on this PC can.
3. **Nothing reported the six days of failures.** Background refresh runs with notifications off; the `Refresh All Apps` Shortcut action returns "All apps have been refreshed." even when it hits its 27-second deadline; SideStore's My Apps countdown is only visible when someone opens SideStore; the Danner Apps warning appears only in the last 48 hours and tells the owner to charge the phone.
4. Secondary, not the cause this time: on 09-30 the loopback VPN was up but the device endpoint was unreachable (the cached RemotePair port / VPN-started-off-Wi-Fi problem seen on 2026-09-17, which a reboot fixes), and the phone was off Wi-Fi for the last attempt. The phone has been up since 2026-09-23 22:00 UTC.

What it is **not**: the app (its code is irrelevant to profile expiry), certificate revocation (the same certificate serial is in every log, no revocation or OCSP failure), memory kills (no Jetsam entry for SideStore or Danner Apps), or the Shortcut's VPN ordering. `Start VPN` while already connected is a no-op in LocalDevVPN's source, and the identical Shortcut flow refreshed successfully 90 times through 09-23.

## The owner's VPN question

"If the shortcut fails and doesn't turn the VPN off, does the next run fail because the VPN was never shut off?" No. LocalDevVPN's `Start VPN` returns immediately when the tunnel is already up, and SideStore re-probes the tunnel on every refresh. A tunnel left up is harmless. What does break refreshes is a tunnel brought up while Wi-Fi is off (it reports connected but routes nothing) and the RemotePair port drifting after long uptime; both show up in the logs as the `DeviceEndpointNotInitialized` error and both are fixed by a reboot.

## Recovery (needs the owner for the Apple sign-ins)

1. Phone: tap OK on the "No Longer Available" dialog(s). Stay on the home Wi-Fi.
2. PC: iLoader → the saved login → Sign in with the current password (2FA prompt appears on the phone; type the code in iLoader). If it still fails with -22406, reset the Apple Account password first, then Delete the saved login and Add Account.
3. PC: iLoader → `SideStore (Nightly)` with the phone selected. This reinstalls SideStore in place with a fresh 7-day profile; SideStore's database, pairing file, and logs survive the upgrade.
4. Phone: open SideStore → Settings → sign in again (same account; this stores a new token) → LocalDevVPN Connect → My Apps → `Refresh All`. Danner Apps comes back without reinstalling; `console-summary` then shows a new SUCCESS and a new expiry seven days out.
5. Prove the automation: `python iphone_harness.py watch --seconds 240`, unplug, plug in, watch `shortcutsd`/`siriactionsd` start SideStore and the refresh succeed, then `console-pull` + `console-summary`.

## Making it as durable as Android without a paid account

- **Keep SideStore, remove the silent failure.** Check `python iphone_harness.py status` weekly (it flags SideStore not having run for more than a day) and run `console-summary` for the real expiry. Change the Danner Apps warning text so it says to open SideStore and sign in (app change, owner's call). Reboot the phone once a week to keep the RemotePair port at its default.
- **Or move the Apple sign-in to this always-on PC.** AltStore + AltServer on this Windows PC refresh over the home Wi-Fi and re-authenticate with the stored password on every refresh, so a dead token does not stop them; 2FA is still needed when Apple demands it. That trades the PC-less design for one that does not depend on a nine-day token.
- The only ways to stop the 7-day cycle entirely are a paid Apple Developer account (excluded) or shipping the iPhone side as a web app with no native code (drops Cast, the native player, and the TV Location geolocation injection).
